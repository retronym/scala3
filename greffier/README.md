# Greffier

A replayable record of a Scala 3 compile. The compiler (this branch) records every phase's tree, the typer's decisions, symbol changes, lineage between tree nodes and the generated bytecode into one stream; a static web viewer scrubs through it.

Demo: https://greffier.zaugg.id.au (twelve recordings of the small corpus in `corpus/`; the larger `dotc/util` recordings are not published yet).

This is a proof of concept, written with LLM assistance throughout (see `LLM_POLICY.md`). Nothing here is upstream-ready; `DESIGN.md` says what would be.

## How it works

- **Recorder**: `local/replay/plugin` is a `ResearchPlugin` that unfuses miniphases (except one group that depends on fusion order), interleaves a `Record` phase after every phase, interns tree nodes by identity into a dense arena, prints each version with node offsets via a marking `RefinedPrinter`, and observes the typer through `TyperObserver` (`Typed`, `Adapt`, `Complete`, `ImplicitSearch`/`Candidate`, `Report`, copier lineage). The backend hooks add per-class bytecode versions, tree→instruction-range lineage and optimiser passes as phases. `REPLAY_VARIANT=fork` uses the in-tree hooks; `REPLAY_VARIANT=agent` installs the same observer on an unmodified compiler via `-javaagent` and produces byte-identical output.
- **Stream**: JSONL, one record per line, schema in `local/replay/SCHEMA-v1.md`. Append-only; versions share unchanged nodes, so a recording is a few times the size of the typed tree plus the event log.
- **Viewer**: loads a stream (streamed, lazily decoded), shows the printed tree per phase with new/retyped/rebuilt nodes marked, the typer events for a node, per-phase change scores, a project explorer, side-by-side units, a dependencies panel, the bytecode per class linked to the tree, and animated transitions between versions.

## Running it locally

Record the corpus (needs the compiler built in this worktree; see `local/replay/REPORT-reconcile.md` for the variants):

```bash
local/replay/plugin/build.sh && local/replay/plugin/record-corpus.sh
```

View:

```bash
ln -s ../../local/replay/out greffier/ui/data && (cd greffier/ui && python3 gen_index.py data) && (cd greffier && python3 -m http.server 8766)
```

then open http://localhost:8766/ui/ and pick a recording.

Deploy (needs `wrangler login`, and R2 enabled on the account for recordings over 25 MiB):

```bash
greffier/deploy/build.sh --upload --deploy
```

## Status

See the "Decisions" and "Results" sections of `DESIGN.md`. In short: the phase axis, typer events, lineage, bytecode and reproducibility all work on the corpus and on `dotc/util`; the agent removes the need for a fork; what the educational UI still lacks most is per-definition typer snapshots and a learner-grade type printer.
