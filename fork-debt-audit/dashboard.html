Scala 2 → Scala 3 untracked fork debt

Code copied from scala/scala into dotty with no cross-porting process. Comparing scala3 a98b104aaa (2026-10-21) against scala/scala 2.13.x a0ebc676ba. Updated: all 10 avenues reported, 2026-10-22.

Provenance: only 6 of the 67 compiler files with substantial 2.13.x overlap carry any comment naming their scala/scala origin or commit; the library fork was grafted with full scala/scala history.

Assessment

Three kinds of debt, and what a process would need
  • Missed 2.13.x fixes (classic fork debt). Concentrated where no re-sync ever happened: classpath resource management (A1-A4, 2019-2025 upstream work), the string-interpolator rewrites (G1, G2), array-store codegen (C1, a 2016 fix), scanner/line-table details (E1-E3), argfile tokenizer (B1). Areas that were re-synced wholesale (FileWriters 2023, AbstractFileClassLoader 2025, backend layering 2022, optimizer 2026, stdlib 2025) are clean up to their sync point.
  • Drift introduced by local refactors of forked code. Rewriting a copy without an upstream reference produced regressions of its own: the 2026 IO encapsulation refactor (A5 reproduced, A6), the "warn when catching Errors" sweep that narrowed Throwable to NonFatal in Promise/LazyList/BatchingExecutor (I1-I3), the optimizer's interface lookup (D1, D2). These are not visible to any "list upstream commits since X" tool; they need a periodic semantic diff against upstream.
  • Reverse debt. Fixes made in Scala 3 copies that 2.13.x never received: in the compiler, the inliner's JDK module-export check (R1), NUL dropped from Java string constants (R2), box-unbox cost guards (R3) and three low ones; in the library, Enumeration.iteratorFrom (I8) and seven collection perf/null fixes (I10). An inner fork: library-js/src full-file overrides that missed fixes to library/src (I9). The TASTy reader, where Scala 2 must track Scala 3, is not drifting: it is re-synced per Scala 3 minor and byte-identical to 3.7.x, with a deliberate freeze at 28.7 (H1).
  • Process today. Compiler: none. 6 of 67 overlapping files name their origin; the optimizer port names no base commit. Library: project/scripts/syncStdLib.scala writes Upstream: scala/scala@sha footers but was used once (4 commits); the 31 upstream commits since v2.13.18 were hand-ported or missed.
  • Machine assistance that would have caught most of this. (1) A checked-in file-pair map (this scan's sim_tok.tsv is a first draft: 67 compiler pairs, 495 library pairs) with the last-synced upstream sha per pair. (2) A CI/cron job that lists 2.13.x commits touching mapped origin paths since that sha and opens an issue per unported fix. (3) For the drift class, a normalized diff (whitespace, braces, Scala 3 syntax) per pair, reviewed when either side changes.

Avenues of exploration

A · Classpath & IO done

dotc/classpath/*, tools/io/*, config/PathResolver ← nsc/classpath, reflect/io, nsc/util/ClassPath

Ported 2017-04, then rewritten again in 2026. The whole 2019-2025 scala/scala resource-management line (closeable registry, refcounted cache, release in cache key, ct.sym caching) is absent: 4 medium, 4 low. FileWriters and AbstractFileClassLoader were re-synced (2023, 2025) and are clean. Two findings (A5, A6) are Scala 3-only regressions from the 2026 refactors.

B · Settings & CLI done

config/{Settings,ScalaSettings,CommandLineParser,Properties,ScalaVersion,CliCommand} ← nsc/settings/*, sys/process/Parser, util/Properties

Settings itself is a rewrite (compared by behaviour). 1 confirmed missed fix (B1, reproduced), 5 low. Already ported: scala/bug#12611 escaped quotes, string-setting arg guard, space-separated choice args.

C · Backend codegen done

backend/jvm/{BCode*,BTypes,GenericSignatures,CodeGen} ← nsc/backend/jvm

Ported 2017, re-synced to the 2.13 CodeGen/PostProcessor layering in 2022 (fa9648259d), optimizer port Feb 2026 brought more. What the syncs skipped is where the debt is: array stores (C1, VerifyError, reproduced on 3.10.0 and confirmed here), static forwarders (C2), generic signatures of generic inner classes (C4). 1 high, 2 medium, 2 low. try/finally, synchronized, string switch, indy concat spilling all checked OK at runtime.

D · Backend optimizer done

backend/jvm/{opt,analysis}/* ← nsc/backend/jvm/{opt,analysis}

Ported in one commit e86be00cfb (2026-02-09) from the 2.13.x tip; no file cites the base. Only 2.13 change since: IINC fix (already both ways) and ASM analyzer limits (D5). Full normalized diff read: box/unbox, closure rewriting, local-opt fixpoint and all analyzers logically identical. 2 medium (D1, D2, both verified by running the compiler jar), 4 low. Deliberate divergences: stricter Limits, mixin-forwarder inlining, signature-visitor throws (#26632).

E · Parsing done

parsing/{JavaParsers,JavaScanners,Scanners,xml/*}, util/{Chars,SourceFile} ← nsc/javac, ast/parser

Java parser is largely in sync; since 2024 most fixes went Scala 3 → 2. Debt sits in the scanner/line table and XML: unclosed text block crash (E1), no bidi check (E2), form feed shifts line numbers (E3). 3 medium, 5 low (two are shared gaps, not missed ports). All reproduced on the 3.10.2 nightly.

F · Classfile & Scala 2 pickles done

core/classfile/*, core/unpickleScala2/* ← symtab/classfile, reflect/internal/pickling

Little debt: ClassfileParser/Unpickler rewritten, most 2.13 fixes re-implemented independently (CONSTANT_Dynamic, JDK 21 MethodParameters index 0, PermittedSubclasses/Record, SI-9937, SI-7455). Some fixes flowed 3→2. 5 findings, 1 medium (F2).

G · Misc utilities done

profile/*, util/{WeakHashSet,CommentParsing,NameTransformer}, Comments, ConstFold, localopt/{FormatChecker,StringInterpolatorOpt}, Constants

ConstFold, Constants, CommentParsing, WeakHashSet, NameTransformer, ExtendedThreadMxBean in sync. The string-interpolator rewrites are the debt: 2 medium (G1, G2, both reproduced on 3.7.3), 6 low. Side note: Constant.stringValue NPEs on a null constant (Scala 2 returns "null").

I · Standard library fork done

library/src, library-js/src ← src/library

Base: scala/scala 0e9026785e (2025-04, between v2.13.16 and v2.13.17), history grafted in 13fd5af95d (2025-07). A sync script exists (project/scripts/syncStdLib.scala, Dec 2025) and writes Upstream: footers, but was used once for 4 commits; the 31 commits since v2.13.18 were hand-ported or not at all. Far better synced than the compiler. The worst items are Scala 3-only semantic changes (I1-I3, "warn when catching Errors") and the inner library-js fork (I8, I9).

H · TASTy reader (3 → 2.13) done

scala/tools/tasty, nsc/tasty ← tasty/src, dotc/core/tasty (TastyFormat 96%)

Not drifting: Scala 2's format layer is identical to Scala 3.7.x and is re-synced per Scala 3 minor (3.4, 3.5, 3.6, 3.7 so far), tested against 3.7.4. Debt is the deliberate freeze at 28.7 (H1), a version gate that was a no-op in 2.13.13-2.13.18 (H3, fixed on 2.13.x, unreleased), one unported hardening fix (H2). Side find: a disabled catch in Scala 3's SymbolLoaders (H4). ClassfileParser TASTY-attribute and .tasty sibling handling match.

R · Reverse sweep, compiler (3 → 2.13) done

Areas A-G revisited from the other side: Scala 3 bug fixes in the copies that 2.13.x never received.

6 unported fixes, 3 medium (R1 inliner ignores JDK module exports, R2 Java scanner drops NUL from string constants, R3 box-unbox cost guards), 3 low; five reproduced on 2.13.19-M1. Checked and not gaps: super-call receiver, NaN compares, the 2024+ Java-parser and ClassfileParser fixes (already flowed 3 → 2), 712 Java test files parse. Stdlib reverse debt is in I (I8, I10).

Method
  • Two mechanical scans over scala3 (compiler/src, library/src, tasty/src, …) vs scala/scala 2.13.x src/{compiler,reflect,library}: exact normalized-line overlap, and identifier 6-gram shingle overlap (catches files rewritten into Scala 3 syntax).
  • Per avenue, a Sonnet agent pairs files, finds the port date via git log --diff-filter=A, lists 2.13.x commits to the origin file since then, and verifies each bug-fix commit against the Scala 3 copy (diff hunks, grep, git log --grep).
  • Findings carry severity and confidence; "verified" means the agent checked the fix is not implemented elsewhere in Scala 3.
